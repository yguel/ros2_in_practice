DOMAINS

Domains in Brief

As explained in the previous section, the default middleware used by ROS 2 for communication is DDS. In DDS, the main mechanism allowing different logical networks to share a physical network is called the domain ID. ROS 2 nodes on the same domain can discover and send messages to each other freely, while ROS 2 nodes on different domains cannot. All ROS 2 nodes default to domain ID 0. To avoid interference between different groups of computers running ROS 2 on the same network, a different domain ID must be set for each group.

Choosing a Domain ID

To simply choose a safe domain ID, select a domain ID between 0 and 101 inclusively.

For detailed explanations on the range of domain IDs to use in ROS 2, please refer to the official ROS 2 documentation.

Using a DOMAIN ID in Practice

To set the domain ID before running a launch file in ROS 2, you can set the ROS_DOMAIN_ID environment variable in your terminal session.

Open your terminal and set the ROS_DOMAIN_ID environment variable to the desired value (e.g., 42):

export ROS_DOMAIN_ID=42

This command sets ROS_DOMAIN_ID for the current terminal session.

With ROS_DOMAIN_ID set, you can run your ROS 2 launch file:

ros2 launch <package_name> <launch_file_name>

Replace <package_name> with your package name and <launch_file_name> with your launch file name.

By setting ROS_DOMAIN_ID before running the launch file, all nodes initiated by this file will operate in the specified domain, ensuring their communication with other nodes in the same domain.

To make ROS_DOMAIN_ID persistent, it can be added to your user’s .bashrc or .zshrc file.

echo "export ROS_DOMAIN_ID=42" >> ~/.bashrc
